# REQ-005: Audit Logging

> **Superata (2026-08-16).** Requisito non implementato: vedi [ARC-002](../architecture/ARC-002.closure-decision.md) e lo [spike sui guardrail MCP](../09-SPIKE-MCP-GUARDRAILS.md).

## Overview

Log all filesystem operations to JSONL audit file for forensic analysis and compliance.

## Functional Requirements

### Audit Log Format

```json
{
  "timestamp": "2026-01-21T10:30:00Z",
  "action": "write",
  "tool": "fs_write_file",
  "path": "/Users/claudio/projects/test.py",
  "user": "claudio",
  "session_id": "uuid-xxx",
  "success": true,
  "execution_time_ms": 12.5
}
```

### Logged Operations

- **Always**: write, delete, move, copy, create_dir
- **Optional**: read, list, search, file_info (controlled by `log_reads` config)

### Log Management

- **Format**: JSONL (one JSON object per line)
- **Rotation**: At 100MB file size (configurable)
- **Location**: `~/.ollama-fs/audit.jsonl` (configurable)
- **Retention**: Indefinite (user-managed)

## Non-Functional Requirements

### Performance
- Logging doesn't block tool execution
- Async writes to log file
- Minimal overhead (< 1ms per log entry)

### Reliability
- Log writes never fail silently
- Partial logs flushed on crash
- Log corruption detected and reported
